# BE-09: Use case list and detail from latest snapshot

Read RPMP Postgres only. Serve list and one-use-case identity plus snapshot counts. No execution history.

Read `docs/plans/USE_CASES_API_2026-09-11.md` and ADR_BACKEND Decision 3.

## In scope

- `GET /api/v1/use-cases` cookie auth, Viewer and Admin in usecase.
- Optional `q`: case-insensitive substring on `use_cases.name`. Empty or omitted returns all.
- Optional `status`: `active` or `inactive`. Invalid value → `400 invalid_request`.
- Sort by `name` ascending. No pagination in this card (expected ~213 rows).
- Aggregate from the **latest successful** snapshot only (`sync_runs.status = success`, newest `finished_at`). Join `process_aggregate_rows` by `use_case_id`. Include use cases with zero process rows (counts are 0, `success_rate` null).
- `GET /api/v1/use-cases/{id}` same snapshot rules. Unknown or malformed id → `404 not_found`.
- Explicit SQL columns. Domain language only (`active`/`inactive`, counts, `failed_count`).
- Tests with seeded `use_cases` + snapshot rows. Stub file is not the list source.
- Freshness object matches dashboard (`status`, `last_successful_refresh_at`). Never synced and no rows: still `200` with `items: []` and freshness that FE can show (same policy as dashboard if a last successful run exists; otherwise `last_successful_refresh_at` may be omitted only if you keep the dashboard pattern of always sending a timestamp — prefer matching dashboard: if never synced, `503 source_unavailable` **or** `200` empty list with `freshness.status` that is not `fresh`. Pick **200 empty list** when `use_cases` is empty; `503` only when the DB is unusable.)

## Out of scope

- Frontend. Swagger. Querying `RPMP_SOURCE_DATABASE_URL` from HTTP.
- `GET /use-cases/{id}/performance`, `/errors`, `/executions`.
- Inventing weekly points or issue tickets.
- Attended/Unattended. Mock statuses Running/Warning/Stopped.
- Changing dashboard JSON.

## Frozen contract

`GET /api/v1/use-cases`

```json
{
  "freshness": {
    "status": "fresh",
    "last_successful_refresh_at": "2026-09-11T02:00:00Z"
  },
  "items": [
    {
      "id": "018f5f71-9cb9-7a61-97e7-d8f33f12b821",
      "name": "Finance/Invoice.Process",
      "status": "active",
      "process_count": 2,
      "successful_count": 100,
      "error_count": 3,
      "stopped_count": 1,
      "failed_count": 4,
      "execution_volume": 104,
      "success_rate": 96.15,
      "environments": ["PROD"]
    }
  ]
}
```

`success_rate` is two decimal places or `null`. `failed_count` is `error_count + stopped_count`. `execution_volume` is `successful_count + error_count + stopped_count`. `environments` is distinct non-empty `environment_name` values, sorted, may be `[]`.

`GET /api/v1/use-cases/{id}`

```json
{
  "freshness": {
    "status": "fresh",
    "last_successful_refresh_at": "2026-09-11T02:00:00Z"
  },
  "use_case": {
    "id": "018f5f71-9cb9-7a61-97e7-d8f33f12b821",
    "name": "Finance/Invoice.Process",
    "status": "active",
    "source_key": "Finance/Invoice.Process",
    "updated_at": "2026-09-11T02:00:00Z",
    "process_count": 2,
    "successful_count": 100,
    "error_count": 3,
    "stopped_count": 1,
    "failed_count": 4,
    "execution_volume": 104,
    "success_rate": 96.15,
    "environments": ["PROD"],
    "processes": [
      {
        "source_process_key": "42",
        "process_name": "Invoice",
        "package_name": "Invoice.1.0.0",
        "environment_name": "PROD",
        "successful_count": 50,
        "error_count": 1,
        "stopped_count": 0,
        "failed_count": 1,
        "executing_count": 0,
        "pending_count": 0,
        "suspended_count": 0,
        "resumed_count": 0
      }
    ]
  }
}
```

Errors use `{ "code", "message" }`. Known codes: `unauthenticated`, `forbidden`, `invalid_request`, `not_found`, `source_unavailable`, `internal_error`.
