# BE-03: Request and startup logging

Human-selected when the operator wants local/API visibility. Independent of FE visual cards.

## In scope

- Log process start after config and DB ping succeed: listen address, allowed origin, `local_http`, JWT TTL. Do not log `RPMP_DATABASE_URL`, `RPMP_JWT_SECRET`, or any secret.
- Log process shutdown on SIGINT/SIGTERM and on ListenAndServe failure (already has `slog.Error` on fatal; keep that).
- HTTP middleware (thin, in `internal/middleware`): `request_id`, method, path (no query string if it might contain secrets; Slice 1 query is unused on login), status, duration in ms.
- Structured `log/slog` JSON or text. Default text for local is acceptable; JSON if you already have a handler. One logger wired from `cmd/api`.
- Tests: middleware records status and duration; assertions must not expect password, JWT, or `Cookie` header values in log output.

## Out of scope

- Gin, Echo, Chi, or any new HTTP framework.
- OpenTelemetry, Prometheus, Grafana, access-log files, log shipping.
- Logging request/response bodies, `Authorization`, `Cookie`, `Set-Cookie`, passwords, JWT strings, employee passwords.
- Changing auth, dashboard, stub adapter, or public JSON contracts.
- Frontend.

## Log shape (minimum)

Startup:

```text
level=INFO msg="API listening" addr=:8080 origin=http://localhost:3000 local_http=true access_ttl=30m
```

Per request:

```text
level=INFO msg="request" request_id=... method=POST path=/api/v1/auth/login status=200 dur_ms=12
```

Failed login still logs `status=401` and path only. No body.

## Acceptance

- [ ] Running `go run ./cmd/api` prints a listening line without secrets.
- [ ] Each HTTP request produces one request log line with status and duration.
- [ ] Login success and `invalid_credentials` do not log password, hash, or JWT.
- [ ] `go test ./...` and `go vet ./...` pass.
- [ ] No new routes. No contract changes.
