# BE-05: RPMP tables for synced operational data

Own the destination schema. No Orchestrator connection yet. HTTP still uses the file stub after this card.

Read `docs/plans/LOCAL_DB_SYNC_2026-09-09.md` and ADR_BACKEND Decision 3 and 8.

## In scope

Migrations + sqlc for RPMP-owned tables (explicit columns, snake_case):

- `use_cases`: id, source_key (unique), name, status (`active`/`inactive` or the RPMP enum already used in domain), updated_at
- `executions`: id, use_case_id, occurred_at, outcome (`success`/`failure` — never raw JobState), source_ref, created_at
- `execution_errors` (or equivalent): id, execution_id nullable, use_case_id, occurred_at, code, label (RPMP language: faulted/stopped/human names), created_at
- `sync_runs`: id, started_at, finished_at nullable, status (`running`/`success`/`failure`), rows_read, rows_written, error_code nullable (no vendor dump in error_code)

Indexes: `executions(occurred_at)`, `executions(use_case_id, occurred_at)`, `sync_runs(started_at desc)`.

Repo methods: insert/upsert use cases, insert executions in batches, insert sync_run start/finish. No `SELECT *`. Tests with `DATABASE_URL` like existing postgres tests.

## Out of scope

- `cmd/sync`, source DSN, dashboard query rewrite, frontend.
- Vendor table names (`Jobs`, `Releases`).
- Swagger.

## Frozen contract

No new public HTTP. Internal row shapes must be usable by BE-07 to satisfy existing dashboard JSON (BE-02 / BE-04).

## Acceptance

- [ ] `migrate:up` creates the four table groups above.

- [ ] Integration tests insert and read with explicit columns.
- [ ] `go test ./...` and `go vet ./...` pass.
- [ ] No frontend edits. File stub adapter unchanged.
