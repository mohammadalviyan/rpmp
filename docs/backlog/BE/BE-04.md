# BE-04: Stub execution trend and error distribution

Gives the dashboard charts real JSON from the same stub Source as BE-02. No Orchestrator client.

## In scope

- `GET /api/v1/dashboard/execution-trend` from existing stub jobs. Bucket by month in the requested or default period. Series: success count, failure count (Faulted + Stopped as failure, same grouping as summary). Do not expose vendor `JobState` integers.
- `GET /api/v1/dashboard/errors` normalized top groups for a donut (at least two RPMP labels derived from stub, for example `faulted` vs `stopped`, human-readable names). Counts must sum to failed executions in the same period when the fixture allows it.
- Same period rules as BE-02 (`from`/`to` optional `[from, to)` or trailing 30 days).
- Auth cookie + Viewer/Admin authz in usecase. `401` / `503 source_unavailable` like summary.
- Tests against the existing fixture. Explicit columns unused (read-only stub).

## Out of scope

- Frontend, new nav, certified KRI.
- Real Orchestrator.
- Attention items, use case list, status overview.
- Changing BE-02 summary contract.

## Frozen contract

`GET /api/v1/dashboard/execution-trend`

```json
{
  "period": {
    "from": "2026-08-07T00:00:00Z",
    "to": "2026-09-06T00:00:00Z",
    "timezone": "UTC"
  },
  "points": [
    {
      "bucket": "2026-03-01T00:00:00Z",
      "label": "Mar",
      "success": 0,
      "failure": 0
    }
  ]
}
```

`GET /api/v1/dashboard/errors`

```json
{
  "period": {
    "from": "2026-08-07T00:00:00Z",
    "to": "2026-09-06T00:00:00Z",
    "timezone": "UTC"
  },
  "groups": [
    { "code": "faulted", "label": "Faulted", "count": 0 },
    { "code": "stopped", "label": "Stopped", "count": 0 }
  ]
}
```

Point `label` is a short month name in English. Do not return `JobState`, `ReleaseKey`, or Orchestrator field names.
