## Frozen contract

`POST /api/v1/auth/login`

```json
{
  "employee_id": "12345678",
  "password": "user supplied secret"
}
```

Success is `200`, sets `rpmp_access`, and returns:

```json
{
  "user": {
    "id": "018f5f71-9cb9-7a61-97e7-d8f33f12b821",
    "employee_id": "12345678",
    "display_name": "Example Viewer",
    "role": "viewer"
  }
}
```

`GET /api/v1/auth/me` returns the same `user` shape with `200`.

`POST /api/v1/auth/logout` expires `rpmp_access` and returns `204` with no body.

Errors use:

```json
{
  "code": "invalid_credentials",
  "message": "Employee ID or password is incorrect."
}
```

Cookie defaults are `HttpOnly`, host-only, `Path=/`, `SameSite=Lax`, `Secure` outside explicit local HTTP development, and a configurable 30-minute TTL. There is no refresh cookie. JWT claims are `iss`, `sub`, `role`, `iat`, `exp`, and `jti`.

## Acceptance

- [x] Valid credentials return `200`, set the cookie, and return the frozen user shape.
- [x] Invalid credentials return a safe `401 invalid_credentials` without identifying which field failed.
- [x] Inactive users cannot log in and cannot keep using a previously issued JWT.
- [x] Passwords use an approved adaptive hash and never appear in logs or audit rows.
- [x] Missing, expired, malformed, and incorrectly signed JWTs return `401 unauthenticated`.
- [x] `me` reloads the user and returns only the frozen fields.
- [x] Viewer and Admin can call read-only protected usecases; authorization is not middleware-only.
- [x] Logout expires the cookie with matching attributes and records an audit event when identity resolves.
- [x] Login success and failure create audit events without passwords, password hashes, or JWTs.
- [x] State-changing auth routes reject an unapproved `Origin`.
- [x] SQL names columns explicitly and generated sqlc files are not hand-edited.
- [x] Formatting, unit/integration tests, race tests, and `go vet` pass.
