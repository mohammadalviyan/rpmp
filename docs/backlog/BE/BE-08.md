# BE-08: Sync status and Admin manual sync

Same job as `cmd/sync`. HTTP must not run a long source query on the request goroutine without a timeout/worker; prefer 202 + background.

## In scope

- `GET /api/v1/sync/status` (cookie, Viewer + Admin): last run id, status, started_at, finished_at, rows_written. No DSN, no vendor errors as message (sanitize).
- `POST /api/v1/sync` (cookie, **Admin only**): start sync if idle → **202** `{ "run_id", "status": "running" }`. If already running → **409** `{ "code": "sync_in_progress" }`. Viewer → **403**.
- Reuse lock from BE-06.
- Tests for authz, 202, 409, 403.

## Out of scope

- Frontend button (FE-13). Changing dashboard KPI JSON. Swagger.

## Frozen contract

`GET /api/v1/sync/status`

```json
{
  "run_id": "018f5f71-9cb9-7a61-97e7-d8f33f12b821",
  "status": "success",
  "started_at": "2026-09-09T00:00:00Z",
  "finished_at": "2026-09-09T00:01:00Z",
  "rows_written": 100
}
```

`status` is `running` | `success` | `failure` | `never`. `run_id` and timestamps may be null when `never`.

`POST /api/v1/sync` success:

```json
{
  "run_id": "018f5f71-9cb9-7a61-97e7-d8f33f12b822",
  "status": "running"
}
```

- [ ] Admin POST 202 and second POST 409 while running.
- [ ] GET never logs/returns source DSN.
