# FE-02: Dashboard KPI cards

Blocked until BE-02 and FE-01 are complete and a human selects this card.

## In scope

- Fetch the protected Dashboard summary from the RPMP API.
- Render Total Use Cases, Active Use Cases, Execution Volume, Success Rate, and Failed Executions.
- Show the response period and last successful refresh.
- Render `success_rate: null` as `N/A`.
- Add loading, unauthenticated, source-unavailable, and empty states.
- Use a Server Component for the initial read unless implementation evidence requires a client boundary.
- Add focused component and route tests.

## Out of scope

- Any backend, fixture, metric, normalization, or auth changes.
- Recomputing Success Rate or status mappings in React.
- Trends, charts, errors, attention items, filters, polling, health, and SLA.
- Orchestrator fields, calls, credentials, or robot controls.

## Frozen contract

`GET /api/v1/dashboard/summary` returns:

```json
{
  "period": {
    "from": "2026-08-07T00:00:00Z",
    "to": "2026-09-06T00:00:00Z",
    "timezone": "UTC"
  },
  "freshness": {
    "status": "fresh",
    "last_successful_refresh_at": "2026-09-06T00:00:00Z"
  },
  "kpis": {
    "total_use_cases": 12,
    "active_use_cases": 9,
    "execution_volume": 100,
    "success_rate": 94.0,
    "failed_executions": 6
  }
}
```

`success_rate` is `number | null`. Errors use `{ "code": string, "message": string }`. The frontend displays values and does not reproduce the stub formulas.

## Acceptance

- [ ] All five FR-2.2 KPI cards render from the frozen response fields.
- [ ] Success Rate is formatted as a percentage without recalculation.
- [ ] A null Success Rate renders as `N/A`, not `0%`.
- [ ] Period and last successful refresh are visible in human-readable form.
- [ ] Unauthenticated responses follow the FE-01 auth flow.
- [ ] Source-unavailable and empty states do not present stale data as current.
- [ ] Labels use RPMP terms and remain understandable without color.
- [ ] Initial data loading follows the frontend ADR's Server Component default.
- [ ] No backend files, formulas, or contracts are changed.
- [ ] Frontend type, lint, and test commands pass.
